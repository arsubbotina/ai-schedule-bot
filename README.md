# AI Schedule Bot

Telegram-бот для учебного расписания и дедлайнов с хранением данных в SQLite
и рекомендациями GigaChat. Личный учебный проект Анастасии Субботиной.

## Задача и возможности

Расписание и сроки сдачи удобно хранить в одном интерфейсе. Бот позволяет
добавлять занятия и дедлайны, смотреть расписание на день и неделю,
отмечать выполненные задачи и задавать предпочтения для AI-рекомендаций.

Основные команды: `/start`, `/help`, `/today`, `/tomorrow`, `/week`,
`/deadlines`, `/analyze`, `/preferences`, `/subjects`, `/delete`, `/notify`.
Наличие команды настройки уведомлений не означает наличие фоновой доставки:
полноценный планировщик напоминаний в этой версии не реализован.

## Устройство

`Telegram → обработчики Python → SQLite`

`Запрос анализа → GigaChat API → ответ в Telegram`

В базе пять основных таблиц: users, schedule, notifications, deadlines,
user_preferences. Расписание выбирается по пользователю и дню; используются
параметризованные SQL-запросы. Реализация находится в `bot.py`.

## Запуск

Нужны Python 3.10+, токен Telegram-бота и собственный ключ GigaChat API.
Ключ GigaChat имеет формат Base64 от `client_id:client_secret`.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Заполните `.env` локально. Этот файл не загружается Python автоматически.
Для macOS/Linux экспортируйте значения перед запуском:

```bash
set -a
source .env
set +a
python bot.py
```

По умолчанию создаётся `schedule_bot.db` в текущем каталоге. При повторном
запуске записи сохраняются. Путь можно задать через `SCHEDULE_DB_PATH`.
Если API требует дополнительный доверенный сертификат, укажите путь к
CA bundle в `SSL_CERT_FILE`; проверка TLS включена.

## Проверка

```bash
python -m unittest discover -s tests -v
```

Локальные тесты проверяют сохранность базы после повторной инициализации,
порядок занятий и разделение расписаний пользователей. Они не вызывают Telegram
или GigaChat. Полный запуск с внешними API требует действующих ключей и отдельно
не проверен при подготовке репозитория. Диапазоны зависимостей — начальные
ограничения, а не зафиксированное протестированное окружение.

## Ограничения и развитие

- Это учебный прототип в одном модуле; нет миграций БД и мониторинга.
- AI-рекомендации могут содержать ошибки; их качество количественно не оценено.
- Во внешний AI передаются сведения из расписания и задач. Для демонстрации
  используйте вымышленные данные.
- Следующие шаги: разделить обработчики, БД и API-клиент; добавить фоновые
  напоминания и проверки сценариев пользовательского ввода.

## Подготовка к публикации

Ключи вынесены из кода в окружение, удалён вывод частей ключей в консоль,
включена проверка TLS, убрано удаление базы при старте. Исходный файл
`project03_tast01.py` совпадал с `TG.py`, поэтому опубликована одна копия.
База пользователей и действующие ключи в репозиторий не включаются.
